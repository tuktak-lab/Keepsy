# Verification

- 실제로 실행한 검사만 "통과"라고 쓴다. 못 한 검사는 못 했다고 보고와 PR에 적는다.
- 검사를 통과시키려고 기준(요구사항 · 테스트 · 검사 스크립트)을 약하게 고치지 않는다.
- 버그 수정은 가능하면 재현 테스트를 먼저 추가하거나, 최소한 재현 절차를 적는다.
- 새 기능은 요구사항의 수용 기준(명세서 「상세 / 수용 기준」 열)으로 성공 경로와 주요 실패 경로를 검증한다.
- flaky test를 재실행으로 숨기지 않는다.
- 테스트 전략은 `../docs/docs/DEVELOPMENT.md` 「7」, 실행 명령은 같은 문서 「6」을 따른다. 버전 · 명령은 추측하지 말고 돌려서 확인하고, 확인된 실행 명령만 그 「6」 표에 "확인됨"으로 반영한다.
