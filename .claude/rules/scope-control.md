# Scope Control

작업 중 "같이 고치면 좋아 보이는 것"을 발견해도 범위를 넓히지 않는다.

지금 작업과 무관하면:
1. 문제를 짧게 기록한다 (보고의 「못 고친 것」 또는 별도 이슈 후보).
2. 현재 작업에는 포함하지 않는다.

## 근거 없이 하지 않는 변경

- 폴더 구조 전면 변경, framework/library 교체, 빌드 도구 변경
- dependency 대량 업데이트, formatter 전체 적용, naming 일괄 변경
- API 계약 · DB schema · 권한 정책 변경 (`../docs/docs/CONTRACTS.md` 「5. 계약 변경 절차」를 먼저 따른다)
- CI/CD · 배포 대상 변경
- 문서에 없는 결정을 코드에서 먼저 내리기. 문서에 없거나 문서끼리 어긋나면 사용자에게 묻는다
