# Git 작업 규칙

- 사용자가 요청할 때만 commit · push한다. merge · 이슈 생성 · 라벨 · 저장소 설정 변경도 마찬가지다.
- 첫 커밋(골격 · 설정)은 `main`에 직접 올렸다 (2026-11-23, 저장소 담당자 결정). 그 뒤의 브랜치 · PR · 리뷰 규칙은 `../docs/docs/DEVELOPMENT.md` 「2. Git 전략」을 따른다. 아직 `[제안]`이므로, 팀이 확정하기 전에는 main 직접 커밋인지 PR인지 사용자에게 확인한다.
- 이슈와 PR은 `.github/` 템플릿을 쓰고, 「관련 요구사항」에는 `요구사항명세서.md`의 ID를 그대로 적는다.
- 커밋 하나에는 한 가지 목적만 담는다.
- `main`과 남의 브랜치에 force push하지 않는다. `git config`의 사용자 정보를 바꾸지 않는다.
- `git reset --hard` · `git clean` · 브랜치 삭제처럼 되돌리기 어려운 명령은 미커밋 변경을 확인하고 사용자에게 먼저 묻는다.
